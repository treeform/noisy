# API and downstream compatibility

This audit compares Noisy `9625ee0` (before the permutation fix, native 1D/4D,
and NEON work) with `e2d0a20`. The source API used by existing 2D/3D callers
remains compatible. Generated noise is not identical to the older version.

## Public API

Compiler-generated API manifests retain all 10 original function signatures,
including parameter names, defaults, return types, and exception effects.
`Simplex` and `NoisyError` are unchanged. `Grid` retains `width`, `height`,
`depth`, and `values`, with the original 2D/3D indexing and storage order.

[`tests/test_api.nim`](../tests/test_api.nim) exercises the original API using
named arguments, typed procedure values, mutable noise settings, integer and
float coordinates, public permutation arrays, old object constructors, grid
indexing, and `NoisyError`. It is part of the normal test suite:

```sh
nim check tests/tests.nim
nim r tests/tests.nim
```

The same API fixture is also checked against the baseline, so its expectations
are valid for old clients. New dimensional APIs are covered separately by
`tests/test_dimensions.nim`.

The full suite passed with Nim 2.4.0 on ARM64/NEON and x86/SSE2. The legacy API
fixture also passed with Nim 1.4.8, the minimum at the time of this audit.
On Nim 1.4.8, `initSimplex(0)` triggered the `random.initRand` assertion in both
Noisy versions. A temporary copy omitting only fixed seed-zero cases passed the
full suite on both architectures with Nim 1.4.8.

Compatibility limits:

- The permutation fix intentionally changes samples for existing seeds. Saved
  seeds alone do not recreate terrain generated by the old implementation.
- The additional `Grid.frames` field changes reflection/serialization shape
  and object memory layout. Rebuild consumers, and review formats that serialize
  every field automatically. Original named-field constructors still work.
- The minimum `nimsimd` dependency increased from `0.4.3` to `1.3.2` for NEON.
  Install dependencies with Nimby.

## Downstream checks

These checks used Nim 2.4.0 on macOS ARM64 with the current Noisy source and
NEON backend. Compiler dependency output was inspected to confirm that builds
used this checkout rather than a cached package. Consumer source was not
modified to accommodate Noisy and is not vendored here.

| Public consumer and revision | Actual code exercised | Result | Full application limit |
| --- | --- | --- | --- |
| [Polyworld `62ee8b7`](https://github.com/softmax-universe/polyworld/tree/62ee8b7afbb8e1a3cbeeb10d8a933c97b40ea2b0) | Existing `tests/test_terrainmaps.nim` and terrain modules | All five terrain test groups passed, including repeatability, material selection, and invalid input | The GUI terrain experiment has an unrelated missing `Silky.inputRunes` member. The same error occurs with baseline Noisy. |
| [Photonstomp `ebd44ce`](https://github.com/beef331/photonstomp/tree/ebd44cecabd878c15fabb3ade49ecc58346547cb) | Unchanged `src/raymarch/blocks.nim`; `genChunk(321, 0.05)` | Semantic check and release execution passed, producing 27 million blocks with air, water, and grass | Full GUI checking is blocked by an SDL2 binding and a Pixie/zippy signature mismatch. |
| [Hydrology simulation `7d06679`](https://github.com/12to-the12/hydrology-simulation/tree/7d0667936d9f8a41c433bd0d9dff1e508a933ddf) | Unchanged archived `archive/nimsrc/terrain.nim`; `brownianTerrain` using the project's config | Semantic check and release execution passed: 512 by 512 cells, 16 octaves, finite varied heights and valid normals | The archived full application fails checking at existing float/int comparisons in `erode.nim:80-81`. |

These are integration checks of the real terrain generators. They do not
establish that every graphical application builds or runs with all dependency
versions, and they do not assert identical terrain across the permutation fix.

For a repeat audit, check out the pinned consumer revisions outside Noisy and
use their modules above. Point Nim at this checkout and its Nimby-installed
dependencies. Use a fresh `--nimcache` and inspect the generated build JSON to
verify source resolution. Parent `nim.cfg` files can override package paths;
`--skipParentCfg:on` with explicit dependency paths avoids that ambiguity.
